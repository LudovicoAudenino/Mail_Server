JavaFX Mail System

A comprehensive client-server email system built with JavaFX, featuring a modern graphical interface, real-time communication, and robust email management capabilities.

System Architecture

The JavaFX Mail System is a distributed application consisting of two main components:

  • Mail Server - Backend server handling client connections and email storage
  • Mail Client - Frontend application providing the user interface

Server Component

The server application provides:

  • TCP socket server listening on port 8888
  • Concurrent client handling with thread pool (max 3 clients)
  • File-based email storage and persistence
  • Real-time server monitoring and logging interface
  • Stateless HTTP-like communication protocol

Client Component

The client application features:

  • JavaFX-based graphical user interface
  • User authentication and session management
  • Email composition, viewing, and management
  • Automatic email refresh and server status monitoring
  • Reply, reply-all, and forward functionality

Communication Protocol

The system uses a custom stateless protocol over TCP connections:

Protocol Commands

  • LOGIN - User authentication and mailbox retrieval
  • SEND_EMAIL - Send new email messages
  • FETCH_NEW_EMAIL - Retrieve undelivered emails
  • DELETE_EMAIL - Remove emails from mailbox
  • REPLY_EMAIL - Send reply to existing email
  • REPLY_ALL_EMAIL - Send reply to all recipients
  • FORWARD_EMAIL - Forward email to new recipients
  • CHECK_EMAIL_EXISTS - Validate email addresses
  • PING - Server connectivity testing

Communication Flow

  1. Client opens TCP connection to server on port 8888
  2. Client sends command string via ObjectOutputStream
  3. Client sends command parameters (if required)
  4. Server processes request and sends response via ObjectOutputStream
  5. Connection is closed automatically (stateless design)

Threading Model

Server Threading

  • Main Thread - JavaFX Application Thread for UI
  • Server Thread - Accepts incoming client connections
  • Client Threads - Process individual client requests (max 3)
  • Daemon Threads - Background operations and cleanup

Client Threading

  • JavaFX Application Thread - UI updates and event handling
  • Network Threads - Background network operations
  • Auto-refresh Thread - Periodic email checking (30s interval)
  • Heartbeat Thread - Server status monitoring (5s interval)

Data Persistence

The server uses file-based persistence:

  • Storage Location - data/database.txt
  • Format - Java serialization of mailbox data
  • Automatic Backup - Changes saved immediately
  • Account Initialization - Missing accounts created on startup

Error Handling

Network Errors

  • Connection timeout detection
  • Server unavailability handling
  • Graceful degradation of functionality
  • Automatic retry mechanisms where appropriate

User Feedback

  • Informative error messages

  • Real-time status indicators
  • Contextual help and guidance
